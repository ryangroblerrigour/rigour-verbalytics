# Deployment
Replace main.py and requirements.txt; add batch_portal.py and portal.html. test_portal.py is optional. Set PORTAL_USERNAME and PORTAL_PASSWORD (at least 16 characters) in Render. Keep existing API settings. Deploy with one worker and one instance; jobs and login sessions are in memory. Visit /portal on your existing service domain. Never enable PORTAL_INSECURE_LOCAL in production. Optional PORTAL_MAX_ROWS=5000, PORTAL_CONCURRENCY=5 (global batch limit; workers per job capped at five), PORTAL_RETENTION_SECONDS=86400 (maximum 24h; cleanup every 30 seconds). Download before logout/restart. No persistent queue or resume after restart. Shared login, not individual audit accounts. Review hosting region, privacy and access requirements before real data. Batch and live traffic share resources; load test before production. Upload one sheet, values only (formatting and formulas not retained), or UTF-8 CSV, 10 MB max. Map required fields or enter fixed values; select only relevant context columns. Test first five rows, then process pending rows; retry failed rows; download Excel. Existing output columns are not overwritten. For charity use proposition_id and all seven ratings, plus previous P5a context for P6. Mock test: python test_portal.py. Live OpenAI and Render deployment not tested.
